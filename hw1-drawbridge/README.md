## Условие задачи

Через судоходный канал проходит разводной автомобильный мост. По дороге прибывают автомобили, а по каналу с двух направлений подходят суда. В обычном состоянии пролёт опущен и открыт для автомобильного движения. Для пропуска судов оператор должен остановить транспорт, закрыть шлагбаумы, дождаться освобождения моста, поднять пролёт и разрешить проход. После прохождения сформированной группы судов пролёт опускается, фиксируется, шлагбаумы открываются и движение автомобилей возобновляется. Подъём и опускание занимают определённое время. Экстренный автомобиль или приоритетное судно может влиять на расписание, но не отменяет обязательную последовательность безопасных состояний.
Требуется разработать консольное приложение, моделирующее работу разводного моста.

**Входные параметры:**

- интенсивность автомобильного и судового потоков;
- вместимость очередей;
- время проезда автомобиля и прохода судна;
- время закрытия шлагбаумов, подъёма и опускания;
- максимальное время ожидания каждого потока;
- стратегия формирования групп судов;
- правила обслуживания приоритетных участников.

**Отображаемые события:**

Программа отображает прибытие, постановку в очередь, закрытие и открытие шлагбаумов, освобождение дорожного полотна, подъём и опускание пролёта, разрешение движения, въезд автомобиля и проход судна.

**Инварианты:**

- подъём не начинается, пока на мосту находится автомобиль;
- автомобиль не въезжает при закрытом шлагбауме или поднятом пролёте;
- судно не проходит под закрытым мостом;
- противоположные разрешения автомобильному и судовому потокам не действуют одновременно;
- переходы между состояниями выполняются в установленном порядке.

**Завершение:**

Моделирование завершается после обслуживания заданного числа участников либо по окончании смены с выводом оставшихся очередей.
Оператор, механизм моста, автомобили и суда являются самостоятельными участниками модели.

## Основные сущности

| Предметная сущность | Программная сущность | Назначение |
|---|---|---|
| Автомобиль | `struct Car` | id, приоритет, состояние, времена прибытия/въезда/выезда, максимальное ожидание, флаг таймаута |
| Судно | `struct Ship` | id, направление, приоритет, состояние, времена прибытия/прохода/выхода, id группы, флаг таймаута |
| Оператор | `struct Operator` | принимает решения о смене режима моста и формирует группы судов |
| Механизм моста | `struct Bridge` | положение шлагбаумов и пролёта, разрешение |
| Поток автомобилей | `Stream cars` | обычная и приоритетная очереди |
| Потоки судов | `Stream ships_up`, `Stream ships_down` | по одному на каждое направление |
| Событие | `struct Event` | время, тип, id участника, направление, приоритет, указатель на участника |
| Очередь событий | `struct EventQueue` | min-heap по времени |
| Генератор случайных чисел | `struct Rng` | воспроизводимый xorshift64* |
| Конфигурация | `struct Config` | входные параметры, разбор аргументов |
| Журнал | `struct Logger` | вывод в stdout и файл |

**Приоритетные участники** хранятся отдельно от обычных: каждый `Stream` содержит две внутренние очереди — `normal` и `priority`. Внутри каждой очереди сохраняется порядок FIFO.

**Переполнение очередей** в условии задачи не оговорено. Если поток заполнен, новый участник не создаётся, а факт отказа учитывается в статистике.

**Проезд машин через мост** смоделирован параллельным: неограниченное количество автомобилей может одновременно находиться на мосту. Каждый покидает мост через `car_cross_time` единиц времени после въезда.

## Состояния моста

1. `ROAD_OPEN` — пролёт опущен, шлагбаумы открыты, едут автомобили.
2. `CLOSE_BARRIER` — шлагбаумы закрываются.
3. `WAIT_ROAD_CLEAR` — ожидание освобождения моста автомобилями.
4. `RAISE` — подъём пролёта.
5. `SHIPS_PASSING` — пролёт поднят, проходят суда.
6. `LOWER` — опускание пролёта.
7. `OPEN_BARRIER` — открытие шлагбаумов.

Переходы выполняются строго в указанном порядке. Перед каждым переходом проверяются инварианты функцией `bridge_check_invariants()`.

---

## Стратегии формирования групп судов

Группа формируется в начале перехода в состояние `SHIPS_PASSING`: оператор собирает список судов, которые пройдут за один подъём пролёта. Размер группы ограничен сверху (`max_group_size`).

Поддерживаются две стратегии:

- **`GROUP_STRATEGY_FIFO`** — суда включаются в группу строго по времени прибытия, независимо от приоритета и направления. Оператор рассматривает головы обеих внутренних очередей обоих направлений и берёт минимальную по `arrival_time`. При равенстве времён приоритетное судно имеет преимущество.
- **`GROUP_STRATEGY_PRIORITY`** — сначала в группу включаются все приоритетные суда обоих направлений в порядке прибытия, затем — обычные в порядке прибытия.

Оба направления движения по каналу обслуживаются одновременно: поднятый пролёт пропускает суда сверху и снизу параллельно.

## Поведение участников

**Автомобиль.** Прибывает через случайный интервал, распределённый экспоненциально. С вероятностью `priority_prob_car` становится экстренным и попадает в приоритетную очередь. При заполненном потоке машина не создаётся, а счётчик отказов увеличивается. При состоянии моста `ROAD_OPEN` все машины из очереди одновременно выезжают на мост: `EV_CAR_ENTER` фиксирует въезд, `EV_CAR_EXIT` через `car_cross_time` — выезд. Машины едут параллельно, ограничений на количество одновременно находящихся на мосту нет.

**Судно.** Прибывает с одного из двух направлений, интенсивности задаются отдельно для верхнего и нижнего. С вероятностью `priority_prob_ship` становится приоритетным. При заполненной очереди направления объект не создаётся, счётчик отказов увеличивается. Когда пролёт поднят (`SHIPS_PASSING`), суда группы проходят под мостом параллельно: `EV_SHIP_ENTER` и `EV_SHIP_EXIT` через `ship_pass_time`. Суда обоих направлений идут одновременно.

**Оператор.** Анализирует длины очередей и инициирует переходы автомата моста:

- в `ROAD_OPEN` — если в очередях судов есть хотя бы одно судно, начинает закрытие шлагбаумов;
- в `WAIT_ROAD_CLEAR` — когда на мосту не осталось машин, запускает подъём пролёта;
- в `SHIPS_PASSING` — когда все суда группы вышли, запускает опускание пролёта;
- в `LOWER` — когда пролёт опущен, запускает открытие шлагбаумов.

Также формирует список судов для очередной группы по выбранной стратегии.

**Механизм моста.** Исполняет команды оператора с заданными задержками: закрытие и открытие шлагбаумов, подъём и опускание пролёта. По завершении каждой операции генерируется соответствующее событие.

## Пользовательский интерфейс

Интерфейс — консольный. Вывод идёт одновременно в стандартный поток и в файл `sim.log`.

В начале работы печатается конфигурация:

```text
=== Конфигурация ===
Интенсивности:   car=0.500, ship_up=0.100, ship_down=0.100
Очереди:         cars=32, ships=16
Времена:         car_cross=2.00, ship_pass=3.00
Шлагбаумы:       close=1.00, open=1.00
Пролёт:          raise=4.00, lower=4.00
Таймауты:        car=60.00, ship=60.00
Приоритеты:      car=0.050, ship=0.100
Стратегия:       FIFO, max_group=5
Завершение:      max_served=50, shift_end=-1.00
Прочее:          seed=1, delay=0.00
====================
```

Далее построчно выводятся события с модельным временем:

```text
[t=   2.54] EVENT: CAR_ARRIVAL
[t=   2.54] EVENT: CAR_ENTER              id=1
[t=   3.20] EVENT: SHIP_ARRIVAL           dir=up
[t=   4.20] EVENT: BARRIER_CLOSE_DONE
[t=   4.54] EVENT: CAR_EXIT               id=1
[t=   8.95] EVENT: RAISE_DONE
[t=   8.95] EVENT: SHIP_ENTER             id=1 dir=up
[t=  11.95] EVENT: SHIP_EXIT              id=1 dir=up
[t=  15.95] EVENT: LOWER_DONE
[t=  16.95] EVENT: BARRIER_OPEN_DONE
```

Для судов указывается направление (`up` / `down`) и id. Для машин — id. Отображаются все ключевые события предметной области: прибытие, въезд на мост, выезд, закрытие и открытие шлагбаумов, подъём и опускание пролёта, вход и выход судов.

По завершении печатается итоговая сводка:

```text
=== Итог ===
Модельное время:        94.50
Обслужено:              cars=38, ships=12
Отказы (очередь полна): cars=5, ships=0
Осталось в очередях:    cars=16, ships_up=1, ships_down=1
```

## Сборка

Требования: `gcc` (или `clang`), `cmake` ≥ 3.15, стандартная библиотека C11, `libm`.

```bash
cmake -S . -B build
cmake --build build
```

Таргеты:

```bash
cmake --build build --target run         # собрать и запустить с умолчаниями
cmake --build build --target clean-log   # удалить sim.log
```

Сборка с санитайзерами:

```bash
cmake -S . -B build -DBRIDGE_SANITIZE=ON
cmake --build build
```

## Варианты завершения

1. **По количеству обслуженных участников** — параметр `--max-served N`. Как только суммарное число проехавших машин и прошедших судов достигает `N`, моделирование останавливается, печатается сводка.
2. **По окончании смены** — параметр `--shift-end T`. В очередь событий ставится `EV_SHIFT_END` на модельном времени `T`. По его обработке выставляется флаг остановки.
3. **По сигналу прерывания** — `SIGINT` (Ctrl+C) и `SIGTERM` через `sigaction()`.

## Воспроизводимость

Все случайные решения (интервалы прибытия, моменты появления приоритетных участников) определяет seed генератора xorshift64*, который передаётся через `--seed`. При одинаковом seed и одинаковых параметрах запуска симуляция полностью воспроизводима: последовательность событий и итоговая статистика совпадают от запуска к запуску.
